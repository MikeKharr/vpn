# Бэклог репозитория `vpn`

Находки, выходящие за рамки PR, в котором их нашли. В работу сами не
берутся: помеченное «Владельцу» ждёт его решения (`AGENTS.md` адвента,
«Объём»).

## Владельцу

### Форму матрицы выкатки не держит ничто, кроме ревью

- **Нашёл:** `platform`, PR A-2 (матрица из двух хостов), 2026-10-07.
- **Что не так.** В `deploy.yml` три свойства матрицы — порядок строк
  (резерв th1 первым), `max-parallel: 1` и `fail-fast: false` — названы
  решением ADR [2026-10-05-2223](adr/2026-10-05-2223-second-server-triplify-failover.md),
  «Решения», п. 2, но не держит их никакой шаг. `actionlint` проверяет
  синтаксис и выражения, а не замысел: снятие `max-parallel` или
  перестановка строк для него корректный файл.
- **Чем это кончится.** Без `max-parallel: 1` оба сервера пересоздаются
  одновременно, и окно «лежат оба» открывается на каждой выкатке — ровно то,
  чего второй сервер должен избегать. Без `fail-fast: false` красный job
  основного отменяет выкатку резерва. Оба отказа тихие: прогон зелёный,
  поведение другое.
- **Что было бы держателем.** Шаг CI, разбирающий `deploy.yml` и сверяющий
  набор строк матрицы, их порядок и два флага; плюс приманки, краснящие на
  каждой мутации. Это новый скрипт и новый job — объём больше, чем правка в
  рамках PR A-2.
- **Почему владельцу.** Новый держатель CI — не попутная правка PR A-2
  («Объём» `AGENTS.md` адвента): объём задаёт владелец.

### `deploy/bootstrap.sh`: первый живой прогон датирован днём исправлений

- **Нашёл:** `reviewer`, ревью PR #25, 2026-10-07.
- **Что не так.** Комментарии `deploy/bootstrap.sh:15, :149, :230, :506`
  называют первый живой прогон на th2 «2026-10-07». Прогон был 2026-10-06
  (журнал th2 `Oct 06 11:22:56`); 2026-10-07 — день PR #21 с исправлениями.
  README и дополнение к ADR 2026-10-06-1054 исправлены в PR #25; правка
  комментариев скрипта — класс A, поэтому не там.

### Принятый ADR 2026-10-05-1546, «Откат»: нет порядка снятия двух PR

- **Нашёл:** `compliance`, ревью PR #16 (публикация 443 второго адреса),
  2026-10-05. Блокирующая — в PR закрыта текстом в `README.md`, «Откат».
- **Что не так.** Раздел «Откат» ADR перечисляет два PR отката — «снять
  `ports`» здесь и «`sni` обратно на `"443:443"`» в `zpq-ai` — но **не
  называет их порядок**. Порядок обратен порядку выкатки и обязателен:
  сначала снять `ports` здесь, потом возвращать `sni`.
- **Чем это кончится, если сделать наоборот.** Пока Xray держит
  `45.91.134.23:443`, запрос `0.0.0.0:443` от `sni` не проходит — та же
  карта `0.0.0.0` у распределителя портов Docker, что задаёт прямой порядок
  (moby, `portallocator.go`, `RequestPortsInRange`). А `sni` к этому моменту
  уже снесён `--force-recreate` его выкатки. Итог: **лежат все имена
  машины**, не только VPN. При верном порядке на минуты лежит один VPN, и у
  него на это время остаётся путь через живой `sni`.
- **Почему это владельцу, а не агенту.** Принятые ADR не редактируются
  (I-12 адвента). Нужен либо новый ADR, либо строка-дополнение к `1546` —
  и то и другое принимает владелец.
- **Что уже сделано, чтобы находка не стоила простоя:** порядок записан в
  `README.md`, «Откат», блоком `[!IMPORTANT]` со ссылкой сюда. То есть тот,
  кто пойдёт откатывать по README, порядок увидит. Не держит этого **ничто,
  кроме текста**: шага CI на порядок двух PR в разных репозиториях нет и
  быть не может.

### Клиентский JSON расходится с ADR 2026-10-05-2223 в трёх строках поведения

- **Нашёл:** `platform`, PR A-3 (`bin/make-happ-json.sh`), 2026-10-06, сверкой
  выхода скрипта с п. 4 ADR; четвёртое расхождение (лишнее правило) — находка
  `reviewer` в том же PR.
- **Что не так.** Список правил в п. 4 ADR исчерпывающий, поэтому лишнее
  правило — такое же расхождение, как отсутствующее. В конфиге, который
  **уже импортирован** в Happ на Mac (профиль «TH failover», выход проверен
  владельцем), против буквы ADR три вещи:
  - **нет** правила `domain:zpq.ai → direct`. Трафик к своим сайтам
    (`zpq.ai`, `challenge.zpq.ai`, `mail.zpq.ai`, `cdn*.zpq.ai`) идёт через
    туннель. Петли это не даёт — th2 другая машина, — но путь лишний, а
    обращение к `cdn2.zpq.ai` из туннеля приходит на th2 к его же маске;
  - **нет** `observatory.enableConcurrency: true`. Зонды к th2 и th1 идут
    последовательно: обнаружение падения медленнее на один таймаут зонда;
  - **есть** правило `{"network": "udp", "port": "443", "outboundTag":
    "block"}`, которого в п. 4 нет. Перенесено из профиля Mac, где без него
    Chrome не открывал страницы Google (запись истории
    [2026-10-04-1912](development-history/2026-10-04-1912-mac-quic-reject-and-verge-copy-perms.md)).
    Цена: QUIC в туннеле недоступен, приложения падают назад на TCP/TLS. Снять
    его без замены нельзя — вернётся тот же дефект; это решение владельца, а
    не попутная правка.
  Четвёртое расхождение — тег балансера `main` вместо `vpn` — косметическое,
  на поведение не влияет и решения не требует. Блок `dns` и правило
  `dns-in → balancer` расхождением не считаются: ADR оставляет их открытыми
  прямо («нужен ли `dns`-блок для доменных правил — выяснится той же пробой»).
- **Почему не исправлено в том же PR.** Любая правка выхода — **переимпорт
  на двух устройствах**, а владелец уезжает в Россию, где переимпорт рвёт
  туннель, то есть требует рабочего VPN, чтобы восстановить VPN. Менять форму
  уже импортированного файла без его решения нельзя.
- **Почему владельцу.** Это выбор между лишним участком пути и отсутствием
  QUIC сегодня — и переимпортом в поездке. Цену платит он.
- **Что уже сделано:** расхождения названы в `README.md`, «Чем выход
  отличается от буквы ADR», со ссылкой сюда; полное равенство текущей формы
  держит шаг CI «Клиентский конфиг Happ собирается, и ядро его принимает» —
  то есть незамеченной эта форма больше не изменится.

### Маска `cdn.zpq.ai` отдаёт `alt-svc: h3=":8444"` — зонд видит внутренний порт

- **Нашёл:** `architect`, подготовка ADR
  [2026-10-05-2223](adr/2026-10-05-2223-second-server-triplify-failover.md),
  2026-10-05, живой `curl -sI https://cdn.zpq.ai/`.
- **Что не так.** Caddy `zpq-ai` на слушателе `:8444` объявляет HTTP/3 на
  своём порту: заголовок `alt-svc: h3=":8444"` уходит наружу через проброс
  REALITY. Снаружи 8444 не существует, то есть заголовок — примета
  «страница отдаётся не с того порта, на который пришли», и он называет
  внутренний порт, который шаг CI `zpq-ai` «Страница маски ничего не выдаёт»
  запрещает упоминать в самой странице.
- **Чем лечится.** Глобальная опция Caddy `servers :8444 { protocols h1 h2 }`
  (по документации; не прогонялось). Правка — в `zpq-ai`, отдельный PR там;
  здесь не чинится.
- **Почему владельцу.** Чужой репозиторий и решение о форме маски, принятое
  ADR `zpq-ai` `2026-10-03-1544`. На сервере 2 этот ADR закладывает
  `protocols h1 h2` сразу (таблица «Индексация, блокировка, взлом, SEO»).

### Причину неудачи XHTTP на сервере в журнале не увидеть

- **Нашёл:** `platform`, PR эксперимента XHTTP (ADR 2026-10-07-0920, шаг 2),
  2026-10-07.
- **Что не так.** Все отказы слушателя XHTTP пишутся через `errors.LogInfo`:
  «invalid padding (…) length: …» (`transport/internet/splithttp/hub.go:146`),
  «stream-one/stream-up/packet-up mode is not allowed» (`:155, :200, :242`),
  «failed to validate path» (`:104`). У нас `loglevel: "warning"`
  (`AGENTS.md`, граница 7), то есть ни одна из этих строк на сервер не попадает.
- **Чем это кончится.** Если профиль «TH mobile» не подключится, со стороны это
  будет неотличимо от «оператор режет» — хотя причиной может быть расхождение
  версий ядра, пути или отрезка набивки. Замер даст «нет» вместо ответа.
  Названия строк и номера сверены с тегом `v26.9.30` 2026-10-07 и после переезда
  слушателя XHTTP в inbound `vless-xhttp` (ADR 2026-10-07-1123) не изменились.
- **Что было бы держателем.** Ничего из CI: это свойство живого прогона. Варианты
  — разовое поднятие `loglevel` до `info` на время эксперимента (ценой того, что
  в журнал попадут адреса обращений — ровно то, от чего граница 7 и стоит), либо
  принять, что отрицательный результат эксперимента неразложим.
- **Почему владельцу.** Уровень журнала на личном VPN — его решение, названное
  границей 7 прямо: «любая правка, добавляющая адреса в журнал или статистику, —
  отдельное решение владельца».
