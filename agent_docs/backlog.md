# Бэклог репозитория `vpn`

Находки, выходящие за рамки PR, в котором их нашли. В работу сами не
берутся: помеченное «Владельцу» ждёт его решения (`AGENTS.md` адвента,
«Объём»).

## Владельцу

### Принятый ADR 2026-10-05-1546, «Откат»: нет порядка снятия двух PR

- **Нашёл:** `compliance`, ревью PR #16 (публикация 443 второго адреса),
  2026-10-05. Блокирующая — в PR закрыта текстом в `README.md`, «Откат».
- **Что не так.** Раздел «Откат» ADR перечисляет два PR отката — «снять
  `ports`» здесь и «`sni` обратно на `"443:443"`» в `zpq-ai` — но **не
  называет их порядок**. Порядок обратен порядку выкатки и обязателен:
  сначала снять `ports` здесь, потом возвращать `sni`.
- **Чем это кончится, если сделать наоборот.** Пока Xray держит
  `45.91.134.23:443`, запрос `0.0.0.0:443` от `sni` не проходит — та же
  карта `0.0.0.0` у распределителя портов Docker, что задаёт прямой порядок
  (moby, `portallocator.go`, `RequestPortsInRange`). А `sni` к этому моменту
  уже снесён `--force-recreate` его выкатки. Итог: **лежат все имена
  машины**, не только VPN. При верном порядке на минуты лежит один VPN, и у
  него на это время остаётся путь через живой `sni`.
- **Почему это владельцу, а не агенту.** Принятые ADR не редактируются
  (I-12 адвента). Нужен либо новый ADR, либо строка-дополнение к `1546` —
  и то и другое принимает владелец.
- **Что уже сделано, чтобы находка не стоила простоя:** порядок записан в
  `README.md`, «Откат», блоком `[!IMPORTANT]` со ссылкой сюда. То есть тот,
  кто пойдёт откатывать по README, порядок увидит. Не держит этого **ничто,
  кроме текста**: шага CI на порядок двух PR в разных репозиториях нет и
  быть не может.

### Клиентский JSON расходится с ADR 2026-10-05-2223 в двух строках поведения

- **Нашёл:** `platform`, PR A-3 (`bin/make-happ-json.sh`), 2026-10-06, сверкой
  выхода скрипта с п. 4 ADR.
- **Что не так.** В конфиге, который **уже импортирован** в Happ на Mac
  (профиль «TH failover», выход проверен владельцем), против буквы ADR нет
  двух вещей:
  - правила `domain:zpq.ai → direct`. Трафик к своим сайтам (`zpq.ai`,
    `challenge.zpq.ai`, `mail.zpq.ai`, `cdn*.zpq.ai`) идёт через туннель.
    Петли это не даёт — th2 другая машина, — но путь лишний, а обращение к
    `cdn2.zpq.ai` из туннеля приходит на th2 к его же маске;
  - `observatory.enableConcurrency: true`. Зонды к th2 и th1 идут
    последовательно: обнаружение падения медленнее на один таймаут зонда.
  Третье расхождение — тег балансера `main` вместо `vpn` — косметическое, на
  поведение не влияет и решения не требует.
- **Почему не исправлено в том же PR.** Любая правка выхода — **переимпорт
  на двух устройствах**, а владелец уезжает в Россию, где переимпорт рвёт
  туннель, то есть требует рабочего VPN, чтобы восстановить VPN. Менять форму
  уже импортированного файла без его решения нельзя.
- **Почему владельцу.** Это выбор между лишним участком пути сегодня и
  переимпортом в поездке. Цену платит он.
- **Что уже сделано:** расхождения названы в `README.md`, «Чем выход
  отличается от буквы ADR», со ссылкой сюда; полное равенство текущей формы
  держит шаг CI «Клиентский конфиг Happ собирается, и ядро его принимает» —
  то есть незамеченной эта форма больше не изменится.

### Маска `cdn.zpq.ai` отдаёт `alt-svc: h3=":8444"` — зонд видит внутренний порт

- **Нашёл:** `architect`, подготовка ADR
  [2026-10-05-2223](adr/2026-10-05-2223-second-server-triplify-failover.md),
  2026-10-05, живой `curl -sI https://cdn.zpq.ai/`.
- **Что не так.** Caddy `zpq-ai` на слушателе `:8444` объявляет HTTP/3 на
  своём порту: заголовок `alt-svc: h3=":8444"` уходит наружу через проброс
  REALITY. Снаружи 8444 не существует, то есть заголовок — примета
  «страница отдаётся не с того порта, на который пришли», и он называет
  внутренний порт, который шаг CI `zpq-ai` «Страница маски ничего не выдаёт»
  запрещает упоминать в самой странице.
- **Чем лечится.** Глобальная опция Caddy `servers :8444 { protocols h1 h2 }`
  (по документации; не прогонялось). Правка — в `zpq-ai`, отдельный PR там;
  здесь не чинится.
- **Почему владельцу.** Чужой репозиторий и решение о форме маски, принятое
  ADR `zpq-ai` `2026-10-03-1544`. На сервере 2 этот ADR закладывает
  `protocols h1 h2` сразу (таблица «Индексация, блокировка, взлом, SEO»).
