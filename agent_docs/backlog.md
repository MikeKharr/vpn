# Бэклог репозитория `vpn`

Находки, выходящие за рамки PR, в котором их нашли. В работу сами не
берутся: помеченное «Владельцу» ждёт его решения (`AGENTS.md` адвента,
«Объём»).

## Владельцу

### Принятый ADR 2026-10-05-1546, «Откат»: нет порядка снятия двух PR

- **Нашёл:** `compliance`, ревью PR #16 (публикация 443 второго адреса),
  2026-10-05. Блокирующая — в PR закрыта текстом в `README.md`, «Откат».
- **Что не так.** Раздел «Откат» ADR перечисляет два PR отката — «снять
  `ports`» здесь и «`sni` обратно на `"443:443"`» в `zpq-ai` — но **не
  называет их порядок**. Порядок обратен порядку выкатки и обязателен:
  сначала снять `ports` здесь, потом возвращать `sni`.
- **Чем это кончится, если сделать наоборот.** Пока Xray держит
  `45.91.134.23:443`, запрос `0.0.0.0:443` от `sni` не проходит — та же
  карта `0.0.0.0` у распределителя портов Docker, что задаёт прямой порядок
  (moby, `portallocator.go`, `RequestPortsInRange`). А `sni` к этому моменту
  уже снесён `--force-recreate` его выкатки. Итог: **лежат все имена
  машины**, не только VPN. При верном порядке на минуты лежит один VPN, и у
  него на это время остаётся путь через живой `sni`.
- **Почему это владельцу, а не агенту.** Принятые ADR не редактируются
  (I-12 адвента). Нужен либо новый ADR, либо строка-дополнение к `1546` —
  и то и другое принимает владелец.
- **Что уже сделано, чтобы находка не стоила простоя:** порядок записан в
  `README.md`, «Откат», блоком `[!IMPORTANT]` со ссылкой сюда. То есть тот,
  кто пойдёт откатывать по README, порядок увидит. Не держит этого **ничто,
  кроме текста**: шага CI на порядок двух PR в разных репозиториях нет и
  быть не может.

### Где лежит приватный ключ выкатки — не записано нигде

- **Нашёл:** `platform`, PR про секреты уровня репозитория (ADR
  [2026-10-05-1643](adr/2026-10-05-1643-private-repo-repository-secrets.md)),
  2026-10-05. В PR закрыто обходным путём — сличением отпечатков
  («Ручные шаги», п. 1), а не записью пути.
- **Что не так.** ADR `2026-10-03-0353`, «Ручные шаги», п. 3 велит завести
  пару ключей выкатки, но путь к приватной половине не записан ни в ADR, ни
  в README. GitHub значение секрета не отдаёт, поэтому при любом переезде
  секретов значение берётся только у владельца — и ищется заново.
- **Почему владельцу.** Путь знает только он; агент его не угадывает
  (норма «не предполагать значения секретов»).
- **Что записать, если решит:** строку в README про файл ключа выкатки
  (путь — не секрет, в отличие от содержимого) или решение ротировать пару
  при каждом таком переезде.
