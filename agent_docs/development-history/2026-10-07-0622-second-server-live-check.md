# [2026-10-07 06:22] Второй сервер в работе: выкатка на оба хоста и живая проверка автопереключения

Файл: `agent_docs/development-history/2026-10-07-0622-second-server-live-check.md`

Итог ADR [2026-10-05-2223](../adr/2026-10-05-2223-second-server-triplify-failover.md)
с поправками [2026-10-06-1054](../adr/2026-10-06-1054-agent-runs-th2-bootstrap-once.md):
цель владельца — «трафик через Таиланд, даже если один VPN упал» — проверена
на живых устройствах.

## Что проверено

- Мерж PR #23 выкатил оба хоста одним прогоном (run 37580024599): `выкатка
  th1` и `выкатка th2` — success, th1 первым.
- Маска th2: `curl --resolve cdn2.zpq.ai:443:160.236.128.28` → 200 с
  настоящим сертификатом, `x-robots-tag: noindex, nofollow`. Маска th1 → 200.
- Mac и iPhone с профилем «TH failover» перешли на th2 без переимпорта:
  `api.ipify.org` → `160.236.128.28`. Ключ REALITY th2 на сервере верен —
  иначе клиент к th2 не подключился бы.
- Резерв: тестовый профиль, у которого адрес th2 заменён на `192.0.2.1`
  (TEST-NET-1), через минуту дал `45.91.134.19`; после возврата рабочего
  профиля — снова `160.236.128.28`. Рабочий профиль при проверке не правился.

## Что не проверено

- Отказ th2 на чужое имя (`--resolve zpq.ai:443:160.236.128.28` → отказ TLS)
  с Mac проверить нельзя: Happ разбирает SNI (`destOverride`) и уводит запрос
  на настоящий `zpq.ai`, поэтому 200 не говорит о th2 ничего. Нужен прогон с
  выключенным клиентом.
- `ignoreip` из PR #21/#22 на th2 не применён: фазы bootstrap прошли до этих
  PR, root закрыт, у `ops` нет пароля для `sudo`. Применить — консоль
  провайдера. До тех пор проверочные `ssh` — только с `-o IdentitiesOnly=yes`.

## Уроки

- Через включённый клиент VPN любой порт любого адреса «открыт» (TUN Happ
  принимает соединение сам): `nc` и «Connection closed» до баннера ssh не
  говорят о сервере ничего. Бан fail2ban адреса выхода th1 выглядел как
  поломка sshd и стоил ложного диагноза и лишней просьбы о перезагрузке.
- Сканер QR в Happ принимает только ссылки: JSON-конфиг переносится через
  общий буфер обмена Apple.
- Мобильная сеть владельца давала через тот же профиль неработающий туннель
  при пинге ~1800 мс; на Wi-Fi тот же профиль работает. Не разбиралось.
