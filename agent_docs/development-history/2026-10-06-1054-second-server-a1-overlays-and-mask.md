## Две находки, которые пришлось закрыть здесь, а не оставить на A-2

1. **`deploy.yml` сломался бы в момент мержа.** Он звал `docker compose up -d
   --force-recreate` без наложения, а с этим PR общий `compose.yml` перестал
   быть запускаемым: публикация порта у `xray` исчезла бы (то есть вход th1
   умер бы), а `render` отказался бы с кодом 2. Правка минимальная: переменная
   задания `HOST: th1`, имя хоста едет на сервер аргументом (`bash -s -- th1`,
   heredoc остаётся в кавычках), все четыре вызова `compose` идут через массив
   с двумя `-f`, и зонд маски берёт **и адрес, и `MASK_NAME`** из наложения
   своего хоста. Литерал `cdn.zpq.ai` в зонде убран: с двумя хостами он дал бы
   зелёный ответ от ЧУЖОГО сервера.
2. **`AGENTS.md` и `README.md` содержали утверждения, становящиеся ложными при
   мерже** («публикация наружу ровно одна», шаг CI с прежним именем, `bash
   bin/make-link.sh mac` без хоста, `bash deploy/put-secrets.sh` без
   `SERVER=`). Правки точечные: границы 3–5, список проверок, таблица файлов и
   команды порядка установки. Полный пересказ топологии в документах — шаг 9
   «Ручных шагов», он остаётся.

## Решение по ходу: bootstrap запускает агент, один раз

Владелец 2026-10-06 на вопрос «Кто запускает скрипт настройки (bootstrap) на
сервере Triplify?» ответил «Разово разрешаю агенту». Отсюда ADR
`2026-10-06-1054` и три следствия в коде:

- форма запуска — `ssh triplify 'bash -s -- ops' < deploy/bootstrap.sh`, то
  есть **со stdin**, а не `scp` + файлом, как велел ADR `2026-10-05-2223`:
  агент не оставляет на сервере ничего;
- классический отказ такой формы (apt читает stdin и съедает остаток скрипта
  — урок адвента 2026-09-07) закрыт формой файла: всё тело в группе
  `{ … } </dev/null`. Bash дочитывает составную команду до закрывающей скобки
  прежде, чем исполнить внутри хоть одну команду;
- разбор аргументов перенесён ДО проверки на root — иначе приманки не
  различали бы «имя отвергнуто» от «я не root».

## Что проверялось и как

Прогон локально (`shellcheck` по `git ls-files '*.sh'`, `actionlint`, восемь
файлов приманок) — зелёный; 138 проверок. Docker локально нет, поэтому шаги
`xray run -test` по каждому наложению, `docker compose config` и `caddy adapt`
проверяет только CI.

Приманка «stdin не съедается» — главный новый случай, и она различает
гипотезы, а не описывает действие: фикстура собирается **из самого
`bootstrap.sh`** по позиции (строка, открывающая группу), сразу после неё
вставляются команда, читающая stdin, и метка. Скрипт кормится **конвейером**
(как ssh). С группой метка печатается; со снятой группой `read` съедает
строку с меткой, и её нет. Обе ветви прогоняются каждый раз, поэтому
«защищено» не выглядит как «нечего защищать».

Отдельно и честно: `</dev/null` у группы — второй держатель того же, и он
слабее. При запуске из файла (stdin перемещаемый) bash сам возвращает
позицию, поэтому снятие одного этого перенаправления приманку не краснит;
проверено на деле. Держит группа, и так это и записано в шапке скрипта.
