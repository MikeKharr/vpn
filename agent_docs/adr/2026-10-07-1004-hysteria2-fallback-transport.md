# [2026-10-07 10:04] Hysteria2 как запасной транспорт к th2: сначала пятиминутная проверка UDP на мобильной сети, строить только по её результату — третьим слушателем того же Xray, без отдельного процесса

Файл: `agent_docs/adr/2026-10-07-1004-hysteria2-fallback-transport.md`

## Статус

**Предложено 2026-10-07.** Повод — решение владельца по ADR
[2026-10-07-0920](2026-10-07-0920-mobile-network-freeze-xhttp-experiment.md),
«Решения владельцу», п. 5: «Hysteria2 как запасной вариант?» → «Отдельный
ADR». Предмет — запасной транспорт к двум тайским серверам на случай, если
эксперимент XHTTP на th1 (тот ADR, шаг 2) не сработает или перестанет
работать. На сервер не ходили, код не написан.

Что этот ADR не пересматривает: два сервера и цель «весь трафик из
Таиланда» (ADR [2026-10-05-2223](2026-10-05-2223-second-server-triplify-failover.md));
клиент Happ в режиме полного JSON (ADR
[2026-10-05-1546](2026-10-05-1546-second-ip-xray-direct-happ-back.md), п. 6);
закрытый список публикаций по хосту (`AGENTS.md`, граница 4); эксперимент
XHTTP идёт своим чередом и этим ADR не трогается.

**Что этот ADR исправляет в принятом ADR `0920`.** Три из четырёх доводов
п. 5 и строки «Hysteria2 / TUIC» в «Альтернативах» того ADR против исходника
неверны, и это проверено прогоном (ниже, «Проверено лично»):

- «Xray их не говорит» — говорит: Hysteria2 есть в Xray-core как outbound с
  2026-01-13 и как inbound с 2026-02-12, в образе `26.9.30` на обоих серверах
  он уже лежит;
- «в JSON с балансировщиком не положить» — кладётся: outbound `hysteria`
  рядом с двумя `vless` под тем же `balancers`/`observatory`, ядро принимает;
- «отдельный серверный процесс» — не нужен: третий inbound в том же
  `config.template.json`, тот же контейнер.

Верными остались два довода: нужна **UDP-публикация** (новая строка в
закрытом списке) и **на T2 QUIC не ходит** по источникам (ниже). Поэтому
решение ниже начинается не со стройки, а с проверки.

Слова, которые дальше встречаются, по одному разу:

- **UDP** — второй способ слать пакеты в интернете, рядом с TCP: без
  установления соединения и без подтверждений; на нём работают DNS, звонки,
  игры и HTTP/3.
- **QUIC / HTTP/3** — современный транспорт браузеров поверх UDP (порт 443);
  Hysteria2 выглядит снаружи как сервер HTTP/3.
- **Hysteria2** — протокол туннеля поверх QUIC с собственным управлением
  скоростью **Brutal**: шлёт с заданной скоростью и не замедляется при
  потерях — потому и держится на плохих каналах, и потому его не любят
  провайдеры.
- **salamander** — надстройка Hysteria2, превращающая каждый пакет в шум без
  признаков QUIC; против сетей, где режут именно QUIC, а не UDP целиком.
- **Маскарад (masquerade)** — что сервер Hysteria2 отвечает тому, кто пришёл
  на его порт без пароля: обычная страница по HTTP/3, а не отказ.
- **TUIC** — другой протокол поверх QUIC; Xray его не реализует, Happ тоже.
- **Пин сертификата** — клиент доверяет серверу не по цепочке удостоверяющих
  центров, а по отпечатку конкретного сертификата, записанному в настройки.

## Решение

**Hysteria2 сейчас не строить. Шаг 0 — пятиминутная проверка без PR на
мобильной сети владельца: ходит ли вообще HTTP/3 (то есть UDP на порт 443) к
иностранным дата-центрам с этой сети и доходит ли по нему 68 КБ целиком.
Строить — только если проверка это показала. Если строить — третьим inbound
того же Xray на th2, наружу `160.236.128.28:443:8443/udp`, с сертификатом
маски `cdn2.zpq.ai` из тома её Caddy и маскарадом на ту же страницу; в
клиенте — отдельный тестовый профиль, а не правка «TH failover». th1 — не
сейчас. TUIC — нет.**

### Шаг 0 — проверка, которая различает гипотезы

С Mac через раздачу с iPhone, **Happ выключен на обоих устройствах**, одной
командой под zsh (первая строка один раз ставит `curl` с поддержкой HTTP/3 —
системный `curl` macOS HTTP/3 не умеет):

```sh
brew list curl >/dev/null 2>&1 || brew install curl
C=/opt/homebrew/opt/curl/bin/curl
{
  echo "== $(date -u +%Y-%m-%dT%H:%MZ) выход: $(curl -s --max-time 8 https://api.ipify.org)"
  for h in cloudflare-quic.com quic.nginx.org www.litespeedtech.com nghttp2.org; do
    printf '%-22s TCP: %-14s UDP/HTTP-3: %s\n' "$h" \
      "$($C -s -o /dev/null --max-time 10 --http2 -w '%{http_code} %{size_download}б' "https://$h/")" \
      "$($C -s -o /dev/null --max-time 10 --http3-only -w '%{http_code} %{size_download}б за %{time_total}с' "https://$h/")"
  done
  printf 'DNS по UDP к 1.1.1.1: %s\n' "$(dig @1.1.1.1 +time=3 +tries=1 +short example.com | head -1)"
} 2>&1 | tee -a ~/Downloads/mobile-diag-quic.txt
```

Что здесь что: четыре имени выбраны по хостингу — `cloudflare-quic.com`
стоит на Cloudflare (адреса, которые на этой сети проходят, ADR `0920`, «Что
измерено»), `quic.nginx.org` — Amazon (Франкфурт, AS16509),
`www.litespeedtech.com` — Amazon (США, AS14618; страница 68 801 байт — больше
порога 15–20 КБ), `nghttp2.org` — Akamai/Linode (AS63949). Каждое имя
опрашивается дважды: по TCP (`--http2`) и только по UDP (`--http3-only`).
Первая строка — адрес выхода: он обязан быть адресом оператора
(`178.130.x.x` у Т-Мобайл), а не `160.236.128.28`, иначе Happ включён и
HTTP/3 режет его собственное правило `udp/443 → block` (бэклог, «Клиентский
JSON расходится…»), а не оператор.

| Что вышло | Что это значит | Hysteria2 |
| --- | --- | --- |
| TCP `200` у всех, HTTP-3 `000 … за 10 с` у всех, включая Cloudflare | QUIC или UDP на 443 режется на этой сети целиком | не строить: salamander против такого не заявлен даже его авторами |
| HTTP-3 `200` у Cloudflare, `000` у трёх остальных | UDP к иностранным дата-центрам фильтруется; Cloudflare — в списке | не строить: наши серверы — иностранные дата-центры |
| HTTP-3 `200` у всех, `www.litespeedtech.com` — `68801б` целиком | UDP к иностранным дата-центрам ходит, порога по объёму на UDP нет | строить — шаг 1 |
| HTTP-3 `200` у всех, но объём обрывается | UDP ходит, но душится после порога | не строить в этой форме; вынести владельцу отдельно |
| TCP тоже `000`, или выход `160.236.128.28` | сети нет или Happ включён | повторить |

Чего эта проверка не умеет, названо прямо: она не проверяет UDP **к нашим
адресам**. На `160.236.128.28:443/udp` и `45.91.134.23:443/udp` сегодня никто
не слушает, а `ufw deny incoming` молча бросает пакет, поэтому любой зонд
туда даёт тишину при любой гипотезе. Это проверка пути «мобильная сеть →
иностранный дата-центр по UDP 443», а не конкретно Таиланда.

### Шаг 2 — только по результату шага 1 и отдельным решением

Если Hysteria2 держит мобильную сеть, встаёт вопрос формы профиля. Положить
третий outbound под балансировщик «TH failover» можно (форма принята ядром),
но балансировщик **не выбирает транспорт по сети**: при `leastPing` живые
`th2` и `th2-hy2` соревнуются временем зонда, а заморозку VLESS зонд не
видит (ADR `0920`, «Почему автопереключение здесь не помогает»). Единственная
форма «сначала Hysteria2, потом VLESS» — `selector: ["th2-hy2"]`,
`fallbackTag: th2` — выбрасывает th1 из цепочки: второго уровня у
`fallbackTag` нет. Поэтому реалистичная форма — отдельный профиль с ручным
переключением, как у XHTTP; что дальше — решение владельца по итогам, не этот
ADR.

## Что известно — по источникам, не по пересказу

Даты — публикации; чтение своё (WebFetch), если не сказано иначе.

- **Xray-core, исходник на тег `v26.9.30`** (тот же, что в образе):
  `proxy/hysteria/` создан коммитом «Proxy: Add Hysteria outbound & transport
  (version 2, udphop) and Salamander udpmask (#5508)» 2026-01-13, inbound —

## Варианты

Разобраны четыре пути, между которыми решение реально висело.

| | Hysteria2 внутри Xray на th2 | Отдельный сервер Hysteria (apernet) | TUIC через sing-box | Hysteria2 на th1 |
| --- | --- | --- | --- | --- |
| Процессов на машине | те же два (+ Caddy) | третий контейнер, свой формат конфига | третий контейнер | те же |
| Клиент | тот же Happ, тот же JSON | Happ, ссылка `hy2://` в отдельном профиле | **Happ не умеет** | тот же |
| Сертификат | том Caddy маски, этот репозиторий | то же или ACME в самом Hysteria | свой | Caddy `zpq-ai` — **другой репозиторий**, расширение контракта |
| Публикация | `:443:8443/udp` на th2 | та же | та же | `45.91.134.23:443:…/udp` |
| Маскарад | та же страница `cdn2.zpq.ai` | то же | — | `cdn.zpq.ai` через `zpq:8444` |
| Держатели CI | `xray run -test`, publication-guard, render.test | ничего существующего: новый формат, новые приманки | ничего | те же |
| Дешёвая проверка | шаг 0 общий для всех | | | |

### Hysteria2 внутри Xray на th2 — рекомендуется, если строить

Один процесс, один шаблон, один образ по digest на оба хоста, те же
держатели CI. Сертификат — настоящий, маски, из тома Caddy: зонд, пришедший
на UDP 443 без пароля, получает ту же страницу `cdn2.zpq.ai`, что и по TCP
443, с тем же сертификатом. Цена и границы — «Последствия».

### Отдельный сервер Hysteria — отклонён

Второй формат конфига и второе место для паролей при нулевом выигрыше:
Xray делает то же самое в том же процессе. Единственное, чего нет у Xray, —
встроенный ACME; но сертификат маски уже есть рядом.

### TUIC — отклонён

Xray не реализует; Happ — только Xray. Нужны были бы и другой сервер, и
другой клиент: это не «запасной транспорт», а второй VPN.

### Hysteria2 на th1 — не сейчас

Сертификат `cdn.zpq.ai` живёт в Caddy проекта `zpq-ai`: монтировать его том
в контейнер этого проекта — новая строка межрепозиторного контракта
(`AGENTS.md`, граница 5) и правка в чужом репозитории ради резерва резерва.
Если Hysteria2 на th2 докажет себя, th1 — отдельное решение.

  ответ аутентификации между версиями изменился. С salamander на обеих
  сторонах — `200`, 767 байт; зонд `curl --http3-only` к такому серверу —
  тишина (`000`), к серверу без salamander — `200 http/3` с содержимым
  маскарада.
- **`xray run -test` не ловит отсутствие TLS у inbound `hysteria`**:
  конфиг с `security: none` проходит `-test` с «Configuration OK», а при
  настоящем запуске падает — `failed to listen … transport/internet/hysteria:
  tls config is nil`. Проверено на 26.9.30.
- `allowInsecure` в клиенте отвергнут обоими бинарями; `pinnedPeerCertSha256`
  принимает hex-строку (`xray tls hash -cert` печатает её как «Leaf SHA256»),
  base64 — отказ `encoding/hex: invalid byte`, массив — отказ `cannot
  unmarshal array`.
- Homebrew `curl` 8.22.0 поставлен на этот Mac (`brew install curl`,
  keg-only, системный `curl` не задет): `--version` содержит `ngtcp2/1.25.0
  nghttp3/1.18.0`. `--http3-only` к петлевому серверу Hysteria2 без
  salamander → `200 http/3`. Команда шага 0 прогнана целиком под zsh с этого
  Mac: TCP `200` у всех четырёх имён, HTTP-3 `000 … за 10 с` у всех — **и это
  ожидаемо**: выход в этот момент `160.236.128.28`, то есть Happ включён и
  его правило `udp/443 → block` режет HTTP/3 первым. Форма проверена, ответ
  с мобильной сети — нет.
- `alt-svc: h3=":443"` у `cloudflare-quic.com`, `quic.nginx.org`,
  `www.litespeedtech.com`, `nghttp2.org` — `curl -sI` с этого Mac; размеры
  страниц 125 959 / 2 523 / 68 801 / 6 324 байт; AS по Team Cymru: 16509,
  14618, 63949; `http3.is` — Fastly, не взят.
- Исходник Xray-core на тег `v26.9.30`: файлы и строки, названные в «Что
  известно»; каталог `proxy/` на теге содержит `hysteria`; история
  `proxy/hysteria` — даты коммитов выше.
- certmagic (`storage.go:235–245`, `master`): сертификат сайта лежит по пути
  `certificates/<issuer>/<имя>/<имя>.crt` и `.key`; окно обновления —
  `RenewalWindowRatio` от срока (`certificates.go:217–225`).
- `deploy/hosts/th2/Caddyfile:50` — `protocols h1 h2`: Caddy маски UDP 443 не
  слушает и `alt-svc` не шлёт (`curl -sI https://cdn2.zpq.ai/` — заголовка
  нет); `deploy/bootstrap.sh:334–336` — `ufw allow 22,80,443/tcp`, UDP не
  открыт, но публикации Docker идут мимо `ufw` (ADR `2223`, п. 1).
- `test/render.test.sh:132–146`, `.github/scripts/publication-guard.sh:307–311`,
  `deploy/render/render.sh:26` — строки, которые меняет шаг 1.

Неподтверждённым остаётся всё, что собрано по документации поставщика или не
прогонялось:

- ходит ли UDP 443 с мобильной сети владельца к иностранным дата-центрам —
  это и есть шаг 0;
- принимает ли Happ на iOS и macOS импорт полного JSON с outbound `hysteria`
  и поднимает ли его в своём TUN — ядро по дате умеет, импорт не пробовался;
  версия ядра в Happ Desktop 4.4.8 не названа в заметках релизов;
- совместимость **именно** ядер Happ (26.9.9 и неизвестное у Desktop) с
  сервером 26.9.30 по Hysteria2: проверена пара 26.3.27 → 26.9.30, не они;
- имя каталога `<issuer>` в томе Caddy th2 (`acme-v02.api.letsencrypt.org-directory`
  или ZeroSSL — Caddy пробует Let's Encrypt первым, при отказе ZeroSSL) и
  что `.crt` содержит полную цепочку — по документации и по треду ntc.party
  25010 («должен быть файл fullchain»); узнаётся первой выкаткой;
- что Brutal на канале Triplify NANO (1 vCPU, «Anti-DDoS, WAF» на сайте
  провайдера) не ловится их защитой как флуд — по документации Hysteria
  Brutal «не замедляется при потерях»;
- помогает ли salamander на T2 — источники 2026 года говорят «нет», своего
  замера нет;
- расход памяти QUIC в процессе Xray при потолке 256 МиБ — не мерился.

## Последствия

Положительные:

- Решение не принимается вслепую и не стоит ни одного PR, пока шаг 0 не дал
  «строить»; по источникам 2026 года наиболее вероятный исход шага 0 —
  «не строить», и это результат, а не провал: закрытая гипотеза с
  доказательством.
- Если строить — без третьего процесса, третьего формата и третьего образа:
  тот же Xray, тот же digest на оба хоста, те же держатели CI.
- Отказ UDP, в отличие от заморозки TCP, **виден** `observatory`: зонд по
  мёртвому UDP не проходит, и под балансировщиком Hysteria2 отпадал бы сам.
  Это свойство транспорта, а не обещание: в шаге 1 профиль отдельный и
  переключается руками.

Отрицательные — и честные:

- **Новая публикация и новый класс трафика с машины.** `160.236.128.28:443/udp`
  начинает отвечать как сервер HTTP/3 с сертификатом `cdn2.zpq.ai`, тогда как
  TCP 443 того же имени HTTP/3 не объявляет (`protocols h1 h2`, нет
  `alt-svc`). Для сканера это сервер, который говорит HTTP/3, не предлагая
  его, — слабая, но примета. С salamander порт отвечает шумом — UDP 443,
  который молча ест пакеты, тоже примета.
- **Одна поломка кладёт оба входа.** Inbound Hysteria2 живёт в том же
  процессе, что VLESS: отказ слушателя на старте (`tls config is nil`,
  неверный путь к сертификату в томе) — это Xray в цикле перезапуска, то есть
  **ни одно устройство не подключается ни по одному транспорту**, при
  зелёном `xray run -test` в CI (прогон выше). Держателя на это сегодня нет;
  честные варианты — шаг CI, запускающий ядро на отрендеренном конфиге без
  `-test` на две секунды, или проверка пути к сертификату в самой выкатке.
  Это новый держатель, то есть объём сверх «одного PR» — назван, не обещан.
- **Сцепка версий клиента и сервера по Hysteria2 жёстче, чем по VLESS.**
  Прогон показал: клиент новее сервера — туннель не поднимается. Ядро Happ
  обновляется без нас; пока сервер на `26.9.30`, а Happ уйдёт дальше,
  следующая такая смена ломает outbound Hysteria2 до поднятия digest в
  compose (один PR на оба хоста). VLESS+REALITY за эти месяцы такого не
  показывал.
- **Brutal против провайдера.** Фиксированная скорость, не реагирующая на
  потери, — это то, что защита Triplify может счесть атакой, а ToS Triplify
  уже принят как риск (ADR `2223`, «Статус»). `brutalUp`/`brutalDown` обязаны
  быть честными цифрами канала, не «побольше», либо `congestion: bbr` —
  тогда Hysteria2 теряет главное своё свойство.
- **Сертификат маски читается процессом Xray.** Приватный ключ `cdn2.zpq.ai`
  становится доступен контейнеру, у которого до этого не было ни одного
  секрета в файловой системе кроме tmpfs с конфигом (общий `compose.yml`,
  комментарий к `render`). Том монтируется только на чтение, но граница
  «секреты видит только `render`» (publication-guard, раздел «секреты видит
  только render») расширяется на ключ TLS маски — и держатель это не ловит,
  потому что ищет `REALITY_PRIVATE_KEY` и `secrets.env`.
- **Память.** QUIC в пользовательском процессе дороже TCP; потолок 256 МиБ
  общий с VLESS, и при нехватке ядро на th2 (1 ГиБ) приходит за Xray первым
  (`oom_score_adj: 500`) — за обоими входами сразу.
- **Белые списки не покрыты и здесь.** При отключении мобильного интернета
  «по белому списку» UDP к иностранному адресу — первое, что исчезает.
- **ADR `0920` принят с неверными доводами в п. 5.** Исправление — этот
  документ; принятые ADR не редактируются (норма адвента), и строка в
  «Альтернативах» того ADR остаётся неверной навсегда — читатель обязан дойти
  до «Статуса» здесь.

## Решения владельцу

1. **Шаг 0** — (а) **прогнать команду на мобильной сети и прислать файл
   `~/Downloads/mobile-diag-quic.txt`** (рекомендуется: пять минут, ноль PR,
   закрывает или открывает всё остальное); (б) не прогонять — Hysteria2
   закрывается как «не проверено, не строим».
2. **Если шаг 0 дал «строить»: форма** — (а) **отдельный тестовый профиль
   Happ, inbound на th2, один PR класса A** (рекомендуется); (б) сразу под
   балансировщик «TH failover» — переимпорт двух устройств ради гипотезы, и
   балансировщик транспорт по сети не выбирает (шаг 2); (в) не строить даже
   при «ходит».
3. **Пароль Hysteria2** — (а) **те же UUID устройств** в поле `auth`
   (рекомендуется: ни одного нового секрета на сервере, `put-secrets.sh` и
   `VARS` не меняются; цена — одна строка открывает устройству оба входа,
   что и так верно для одного устройства); (б) два новых секрета
   `HY2_AUTH_MAC`/`HY2_AUTH_IPHONE` — ввод руками на th2 скрытым вводом.
4. **Сертификат** — (а) **маски, из тома Caddy** (рекомендуется: зонд видит
   ту же страницу с тем же сертификатом; цена — ключ TLS в файловой системе
   Xray и путь, который узнаётся первой выкаткой); (б) самоподписанный с
   пином в клиенте — без тома и без Caddy, но зонд видит сервер HTTP/3 с
   самоподписанным сертификатом на имени `cdn2.zpq.ai`, которое по TCP
   отвечает настоящим.
5. **salamander** — (а) **без, первым прогоном** (рекомендуется: маскарад
   HTTP/3 — заявленная защита Hysteria2; источники говорят, что на T2 шум не
   помогает); (б) вторым прогоном, если первый замёрз — одна строка на
   каждой стороне, без нового PR на клиенте.
6. **th1** — (а) **не сейчас** (рекомендуется); (б) вместе с th2 — правка в
   `zpq-ai` и граница 5.

## Альтернативы рассмотрены

- **Port hopping (`udphop`)** — против блокировки конкретного порта, не UDP
  целиком (документация Hysteria); на этой сети по источникам режется QUIC
  как класс. Плюс каждый порт — новая публикация в закрытом списке.
- **Hysteria2 через CDN** — QUIC через Cloudflare к собственному серверу не
  проксируется; путь через CDN — это XHTTP `packet-up` из ADR `0920`, п. 4.
- **MASQUE (`proxy/masque` в Xray 26.9.30)** — тоже QUIC/UDP, те же
  ограничения сети и меньше источников о поведении под ТСПУ; не разбирался
  как отдельный путь.
- **mKCP, WireGuard-outbound и прочие UDP-транспорты Xray** — тот же класс
  «UDP к иностранному адресу» без маскарада под HTTP/3; хуже Hysteria2 по
  всем столбцам таблицы.
- **Сначала построить, потом мерить** — отклонено: шаг 0 стоит пять минут,
  шаг 1 — PR с новой публикацией, ключом маски в чужом контейнере и риском
  положить оба входа.
