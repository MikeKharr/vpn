# vpn

Личный VPN владельца: VLESS + REALITY на Xray-core. Рабочий вход — порт 443
**второго адреса** сервера, который Xray публикует сам; запасной — прежний
адрес `45.91.134.19` за SNI-маршрутизатором репозитория `zpq-ai`. Клиент —
Happ на Mac и iPhone.

Решение и порядок работ — [ADR 2026-10-03-0353](agent_docs/adr/2026-10-03-0353-vless-reality-personal-vpn.md);
перенос рабочего входа на второй адрес —
[ADR 2026-10-05-1546](agent_docs/adr/2026-10-05-1546-second-ip-xray-direct-happ-back.md).

Репозиторий публичный: ключи, UUID, shortId, ссылки `vless://` и QR сюда
не попадают никогда.

## Что в репозитории

| Файл | Что это |
| --- | --- |
| `deploy/compose.yml` | Две службы: `render` (подстановка секретов в tmpfs) и `xray` (ядро). Публикация наружу ровно одна — `443` **второго адреса** машины в порт `8443` контейнера, то есть прямой вход без PROXY protocol. Запасной вход приходит по сети `edge` от единицы `sni` проекта `zpq-ai` с прежнего адреса. Форму публикации держит шаг `ci.yml`. |
| `deploy/config.template.json` | Конфиг Xray с плейсхолдерами `__ИМЯ__`: VLESS + REALITY + Vision, маска `cdn.zpq.ai`, blackhole на приватные диапазоны. Два inbound: `vless-443` с PROXY protocol (запасной путь от `sni`) и `vless-8443` без него — он и выходит наружу как `443` второго адреса. `target` — внутренний слушатель `zpq:8444` с одной только маской. |
| `deploy/render/` | Скрипт подстановки и entrypoint службы `render`. |
| `deploy/put-secrets.sh` | Кладёт пять секретов в `secrets.env` на сервере скрытым вводом. Запускает владелец. `XRAY_TARGET` — не секрет и живёт в `compose.yml`. |
| `deploy/assert-recreated.sh` | Держатель «Xray пересоздан этой выкаткой»: он читает конфиг только на старте, и непересозданный контейнер означает неприменённые ротацию ключа и отзыв устройства при зелёной выкатке. |
| `deploy/secrets.env.example` | Какие пять значений нужны и какой они формы. |
| `deploy/host-key.pub` | Закреплённый ключ хоста для выкатки. Имя сервера — секрет, его здесь нет. |
| `bin/make-link.sh` | Собирает ссылки `vless://` и рисует QR **в терминале**. Ничего не пишет в файлы. Рабочая ссылка — именем `cdn.zpq.ai` (адрес из DNS), запасная — прежним адресом `45.91.134.19` с тем же `sni`, минуя DNS. |
| `bin/make-clash.sh` | Собирает профиль mihomo для Clash Verge Rev на Mac скрытым вводом в `~/Library/Application Support/vpn/clash-mac.yaml` (`0600`). Запускает владелец. |
| `.github/scripts/secrets-guard.sh` | Сторож: краснеет на UUID, ссылке `vless://`, ключе REALITY (формы `Key`, `Password`, `pbk`, «ключ»), shortId в контексте и изображении. Чего он НЕ держит — сказано в `AGENTS.md`. |
| `test/` | Приманки сторожа, отказы рендера и приманки проверки пересоздания. |

## Порядок первой установки

Полный список шагов владельца — ADR, раздел «Ручные шаги и проверки».
Коротко и по порядку:

1. Секреты выкатки `SSH_KEY`, `SSH_HOST`, `SSH_USER` в environment
   `production` этого репозитория; публичный ключ — в `authorized_keys` на
   сервере.
2. В своём терминале: `docker run --rm ghcr.io/xtls/xray-core:26.9.30 x25519`,
   `uuidgen` дважды, `openssl rand -hex 4` дважды. Сохранить в менеджере
   паролей, никуда не вставлять.
3. `bash deploy/put-secrets.sh` — пять значений уходят на сервер.
4. Мерж этого репозитория **первым**: контейнер встаёт в `edge` и снаружи
   недостижим. Порядок не вкусовой — без него выпуск сертификата
   `cdn.zpq.ai` по TLS-ALPN-01 падает (ADR `zpq-ai` 2026-10-03-1544).
5. Мерж PR `zpq-ai` с единицей `sni` — окно простоя 5–20 с на 443 и 80.

Шаги 4–5 — порядок ПЕРВОЙ установки. Для переезда на второй адрес порядок
обратный: сначала PR `zpq-ai`, привязывающий `sni` к прежнему адресу, и
только потом публикация порта здесь — иначе привязка падает с
`port is already allocated` при уже снесённом контейнере. Шаги целиком —
ADR 2026-10-05-1546, «Ручные шаги».
6. Happ по идентификатору `id6504287215`, затем `bash bin/make-link.sh mac`
   и `bash bin/make-link.sh iphone`.
7. В Happ на Mac и iPhone: Settings → Tunnel Settings → **Xray TUN
   включить**, Mux оставить выключенным (несовместим с Vision). С реализацией TUN по
   умолчанию весь UDP в туннеле не проходит — DNS по UDP 53 и NTP 123
   отваливаются по таймауту при живом TCP (запись истории
   [2026-10-04-0513](agent_docs/development-history/2026-10-04-0513-udp-xray-tun.md)).
8. На Mac DNS сети — публичный резолвер, иначе запросы уходят на роутер
   (частный адрес, он в Direct) мимо туннеля и оператор видит имена сайтов:
   `networksetup -setdnsservers Wi-Fi 1.1.1.1 1.0.0.1`, откат —
   `networksetup -setdnsservers Wi-Fi empty` (нужен для страниц входа
   гостевых сетей). Fake DNS в профиле не включать — с ним имена не
   разрешаются (запись истории
   [2026-10-04-0710](agent_docs/development-history/2026-10-04-0710-dns-leak-mac.md)).
9. Mac с 2026-10-05 — Clash Verge Rev вместо Happ, ради обхода VPN одним
   приложением (Яндекс Браузер): ADR
   [2026-10-04-1726](agent_docs/adr/2026-10-04-1726-mac-client-per-app-bypass.md),
   профиль — `bash bin/make-clash.sh`. Шаги 7–8 про Happ остаются для
   iPhone и для отката. После смены сети проверить маршруты: если сайты
   показывают не адрес сервера — выключить и включить Tun Mode (запись
   истории [2026-10-04-1842](agent_docs/development-history/2026-10-04-1842-mac-verge-verified.md)).
   После импорта профиля в Verge — закрыть его копию со значениями, она
   рождается `0644`:
   `chmod 600 ~/Library/Application\ Support/io.github.clash-verge-rev.clash-verge-rev/profiles/*.yaml`.
   Шаг не разовый: Verge может вернуть `0644` при повторном импорте или
   обновлении профиля (не проверено) — права проверять после каждого
   импорта (ADR 2026-10-04-1726, «Дополнение 2026-10-05», п. 2).

## Откат

- **Без PR, минуты:** A-запись `cdn.zpq.ai` обратно на `45.91.134.19` —
  клиенты вернутся на путь через единицу `sni` в пределах TTL 300. Мгновенно
  — вручную выбрать запасной профиль в Happ (он на прежний адрес и уже
  импортирован выключенным).
- **PR здесь:** снять `ports` у службы `xray` — прямой вход закрывается,
  остаётся только путь через `sni`. Прогон 2–4 минуты. Это отдельное
  решение, а не попутная правка (`AGENTS.md`, граница 4).
- **PR в `zpq-ai`:** `sni` обратно на `"443:443"` — нужно только если второй
  адрес снимается с машины.
- Прежняя схема «Caddy держит 443» — `workflow_dispatch` выкатки в `zpq-ai`
  с прежним sha, 2–4 минуты.
